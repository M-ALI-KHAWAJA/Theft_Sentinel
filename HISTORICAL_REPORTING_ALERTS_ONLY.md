# Historical Reporting: Alerts Only (Incidents Removed)

## Summary

Completely removed incidents from Historical Reporting Dashboard. The module now uses **ONLY alerts** generated by cameras and AI models.

## A. Backend Changes

### 1. New View: `HistoricalAlertReportingView`

**File**: `apps/dashboard/views.py`

**Replaces**: `HistoricalIncidentReportingView`

**Key Changes**:
- Uses `Alert.objects` instead of `Incident.objects`
- Filters alerts by `timestamp` (not `created_at`)
- Aggregates alerts by status: `ACTIVE`, `ACKED`, `RESOLVED`
- Returns summary with `total_alerts`, `active`, `acknowledged`, `resolved`

**Data Source**:
```python
# Only alerts from cameras and AI models
alerts = Alert.objects.filter(timestamp__gte=start_date).select_related('camera_id')
```

**Status Mapping**:
- `ACTIVE` → Active alerts
- `ACKED` or `RESOLVED` → Resolved alerts

### 2. URL Changes

**File**: `apps/dashboard/urls.py`

**Removed**:
- `historical-incidents/` endpoint
- `export-incidents/` endpoint

**Added/Updated**:
- `historical-alerts/` → `HistoricalAlertReportingView`
- `export-alerts/` → `AlertReportExportView` (already existed)

### 3. Alert Export View

**File**: `apps/dashboard/views.py` → `AlertReportExportView`

**Already Implemented**:
- Exports alerts (not incidents)
- Supports CSV and PDF
- Uses `export_type` parameter (not `format`)
- Includes alert fields: ID, Type, Severity, Status, Camera, Location, Timestamp

## C. Data Source Verification

### Alerts Come From:

1. **Camera Feeds**:
   - Alerts generated when cameras detect events
   - Linked via `camera_id` ForeignKey

2. **AI Models**:
   - Alerts generated by AI inference pipelines
   - Stored in `Alert` model with `alert_type`, `severity`, `metadata`

### Alerts Do NOT Include:

- ❌ Manually created incidents
- ❌ Test data
- ❌ External alert sources
- ❌ Any data from `Incident` model

### Alert Model Fields Used:

- `id` - Alert identifier
- `camera_id` - ForeignKey to Camera
- `alert_type` - Type of alert (e.g., "theft", "anomaly")
- `severity` - Alert severity level
- `timestamp` - When alert was generated
- `status` - ACTIVE, ACKED, or RESOLVED
- `metadata` - Additional AI model data (optional)

## D. Historical Reporting Features

### 1. Aggregation

**Supported Periods**:
- Daily
- Weekly
- Monthly

**Aggregated Metrics**:
- Total alerts count
- Active alerts count
- Resolved alerts count (ACKED + RESOLVED)
- Trend calculation (increasing/decreasing/stable)

### 2. Visualizations

**Charts**:
- Line chart: Alert trends over time
- Bar chart: Alert counts by period
- All labels refer to "Alerts" (not "Incidents")

**Tables**:
- Alert summary table with period-based aggregation
- Shows: Date/Week/Month, Total, Active, Resolved

### 3. Exporting

**CSV Export**:
- Contains ONLY alert data
- Fields: Alert ID, Alert Type, Severity, Status, Camera Name, Location, Timestamp
- Filename: `alert_report_{period}_{days}days_{date}.csv`

**PDF Export**:
- Contains ONLY alert data
- Title: "Theft Sentinel – Historical Alert Report"
- Summary statistics: Total, Active, Resolved alerts
- Detailed alert table (first 100 rows)
- Filename: `alert_report_{period}_{days}days_{date}.pdf`

## E. Real-Time vs Historical Separation

### Real-Time Dashboard:
- Shows live alerts (active alerts count)
- Shows current system health
- Shows active camera status
- Updates every 30 seconds

### Historical Reporting:
- Uses stored alert data only
- No real-time streaming
- No incident data
- Aggregated by time period

**No Overlap**: Clear separation between real-time streams and historical aggregation.
